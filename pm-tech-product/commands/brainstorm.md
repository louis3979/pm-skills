# /brainstorm -- Structured Brainstorm

Explore a problem wide-open using named techniques instead of an unstructured idea list, then converge deliberately on a short set of surviving directions.

## Invocation

```
/brainstorm Reduce onboarding drop-off
/brainstorm New monetization angles for the free tier
/brainstorm [describe the problem or opportunity area]
```

## Workflow

### Step 1: Confirm Topic and Goal

Ask if not already clear: what problem/opportunity, and what a useful outcome looks like (a feature list, a root cause, a strategic direction).

### Step 2: Run the Brainstorm

Apply the **structured-brainstormer** skill: pick 4-5 named techniques spanning at least two categories, run each for real, log every idea, then converge with one deliberate method (Affinity Clustering, Impact/Effort, PMI, Forced Ranking, or MoSCoW).

Save the output as markdown.

### Step 3: Offer Next Steps

- "Want me to **validate whether the top direction addresses a real problem** (`problem-validator`)?"
- "Should I **ground this against what we already know** (`pm-memory`'s `memory-ideate`, if project memory is set up)?"
- "Want me to **write a PRD** for the chosen direction (`/write-prd`)?"

## Notes

- Naming each technique out loud is the point — it's what keeps the session from defaulting to the same three ideas every time.
- Don't skip the convergence step — a long raw idea list with no narrowing isn't a finished brainstorm.
