# Hiring Brief

## Purpose

Produce a JD and an interview loop that evaluate the right competencies, avoiding improvised interviews and inconsistent, gut-feel hiring decisions.

## Context

Use an existing JD for this role, if one exists, to update rather than write from scratch.

## Instructions

1. Define the Success Profile before writing the JD: 4-6 concrete core competencies specific to this role (not generic "communication skills, leadership"), each tied to a specific behavioral example from the team's actual work.
2. Write the JD from the Success Profile: describe the role's impact (not just a task list), must-have requirements vs. nice-to-haves — keep must-haves minimal, since a long wishlist self-selects good candidates out.
3. Design the interview loop mapped directly from the Success Profile: every core competency needs at least one round/question evaluating it — don't design rounds first and invent questions after.
4. Write behavioral and case questions per round (behavioral tests real past experience, case tests problem-solving on something new), each with "what a strong answer looks like" attached so interviewers score consistently.
5. Build a simple 1-4 scoring rubric (no-hire / lean no-hire / hire / strong hire) per competency, shared across all interviewers.
6. Define the Debrief Process: who consolidates scores, and the tie-breaking rule when interviewers disagree.

```markdown
# Hiring Brief — <role name>

## Success Profile
| Competency | Concrete behavioral example |
|---|---|

## Job Description
### Role & impact
### Must-have requirements
### Nice-to-haves

## Interview Loop Design
| Round | Competency evaluated | Question type |
|---|---|---|

## Questions & expected strong answers
### Round 1: ...
- Q: ...
  Strong answer looks like: ...

## Scoring Rubric
| Competency | 1 - No-hire | 2 - Lean no-hire | 3 - Hire | 4 - Strong hire |
|---|---|---|---|---|

## Debrief Process
<who consolidates scores, and the tie-breaking rule when interviewers disagree>
```

Once the loop is designed, write it up as a repeatable SOP for the next hire in the same role.

## Notes

- Any Success Profile competency with no round/question mapped to it is a gap — fix the loop design before using it, don't ship it incomplete.
- A must-have list exceeding ~5 items signals requirements are too broad — push back and force prioritization.
- If the role's reporting line or ownership scope is unclear, ask before drafting the JD — a fuzzy scope produces mismatched candidates.
